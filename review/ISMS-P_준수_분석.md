# ISMS-P 인증기준 대비 수업계획서 준수 분석

## 분석 대상
- ISMS-P 인증기준 안내서 (2022.4.22, KISA)
- "AI로 쉬워지는 직장인 업무 자동화" 수업계획서 (Google/Microsoft/Claude 3트랙)

## 분석 목적
이 AI 교육 과정이 **ISMS-P 인증을 받은 기업에서 실시**될 때, 어떤 인증기준을 지키고 있고, 어떤 부분이 위반 리스크가 있는지 분석

---

## A. 잘 지키고 있는 ISMS-P 기준 (7개)

### 1. 2.1.3 정보자산 관리 — 보안등급별 취급절차 ✅

**기준**: "정보자산의 보안등급에 따른 취급절차를 정의하고 이행"

**수업계획서 반영**:
- 1회차에서 **데이터 4등급 분류** 실습 (공개/클라우드OK/사내만/절대불가)
- 등급별로 어떤 AI 도구를 사용할 수 있는지 매핑표 작성
- "3등급 데이터는 로컬 AI만, 4등급은 AI에 절대 넣지 않는다"

**평가**: 기업 보안등급과 직접 연결되는 교육. ISMS-P 심사에서 **교육 증빙자료**로 활용 가능.

---

### 2. 2.2.4 인식제고 및 교육훈련 — 정보보호 교육 ✅

**기준**: "연간 교육 계획 수립, 연 1회 이상 교육, 교육 효과 평가"

**수업계획서 반영**:
- 1회차 전체가 **정보보호 인식 교육** (데이터 유출 사례, 보안 정책, AI 보안)
- 매 회차 **AI 코드 검증 4단계** 반복 (보안 습관화)
- 6회차 **월요일 액션 플랜**으로 교육 효과 측정 가능
- 교육 결과 보고서, 출석부, 평가 설문 등 기록 가능한 구조

**평가**: ISMS-P 2.2.4의 핵심 요구사항을 충실히 반영. 특히:
- "침해사고 사례 교육" → 1회차 삼성 소스코드 유출 사례
- "직무별 전문성 교육" → AI 활용 직무 교육으로 해당
- "교육 효과 평가" → 6회차 종합 프로젝트 발표로 평가 가능

---

### 3. 2.2.3 보안 서약 — 비밀유지 의무 인지 ✅

**기준**: "정보자산 취급자가 내부 정책 및 비밀유지 의무를 명확히 인지"

**수업계획서 반영**:
- 1회차에서 "AI에 넣으면 안 되는 것" 명확히 교육
- 데이터 분류 기준표를 수강생이 직접 작성 → 보안 의무 인지

**평가**: 보안 서약서 자체를 교육에서 다루진 않지만, **보안 의무를 인지시키는 교육**으로서 서약의 실질적 효과를 보강.

---

### 4. 2.4.7 업무환경 보안 — 공용PC, 클린데스크 ✅

**기준**: "개인업무 환경에서 중요정보 유·노출 방지"

**수업계획서 반영**:
- 1회차 보안 교육에서 AI 도구 사용 시 화면 노출 주의
- AI 코드 검증 4단계에서 "API 키 노출" 체크 포함
- 대시보드 로컬 공유 시 "같은 네트워크 내에서만" 제한

**평가**: 업무환경 보안의 AI 시대 확장판으로 볼 수 있음.

---

### 5. 2.5.1 사용자 계정 관리 — 개별 계정 사용 ✅

**기준**: "사용자 계정은 개인별로 발급하여 사용"

**수업계획서 반영**:
- 각 트랙에서 **개인 계정**으로 AI 도구에 접속 (공유 계정 사용 안 함)
- Google 계정, GitHub 계정, Claude 계정 모두 개인별 사용

---

### 6. 2.6.7 인터넷 접속 통제 — 외부 서비스 접근 관리 ✅

**기준**: "인터넷을 통한 정보 유출 방지를 위한 통제"

**수업계획서 반영**:
- 도구별 **정확한 보안 조건 명시** (무료 vs 유료, 학습 정책)
- Google AI Studio 무료 티어 경고 (학습에 사용됨)
- GitHub Copilot Business vs Free 차이 명시
- **로컬 AI(5회차)**로 인터넷 접속 없이 AI 사용하는 대안 제공

---

### 7. 2.9.1 변경관리 — 시스템 변경 통제 ✅

**기준**: "시스템 변경 시 통제된 절차"

**수업계획서 반영**:
- AI가 생성한 코드를 **검증 후 실행** (STEP 3: 검증하기)
- VBA 매크로, Apps Script 등 업무 시스템 변경 시 코드 검증 절차 포함
- "에러가 나면 AI에게 물어보고, 수정 요청 후 재검증"

---

## B. 위반 리스크가 있는 부분 (5개)

### 1. ⚠️ 2.3.1 외부자 보안 — 외부 클라우드 서비스 현황 미식별

**기준**: "외부 시설·서비스 이용 현황을 식별하고 위험을 파악"

**리스크**:
- 교육에서 Google AI Studio, GitHub Copilot, Claude 등 **외부 클라우드 AI 서비스**를 사용
- 기업이 이미 승인한 서비스가 아닌 경우, **ISMS-P 외부 서비스 이용 현황에 미등록** 상태에서 사용하는 셈
- Google Labs (Opal, Mixboard, Pomely)는 "실험적 서비스"로 더 위험

**개선 방안**:
- 교육 전 기업의 **승인된 외부 서비스 목록** 확인 필수
- 미승인 서비스는 **더미 데이터로만** 실습하거나, 강사 시연만
- 수업계획서에 **"사전 IT 협조 체크리스트"**에 외부 서비스 승인 항목 추가 → **이미 포함됨** (부록)

---

### 2. ⚠️ 2.6.3 응용프로그램 접근 — 비인가 프로그램 설치

**기준**: "불필요한 서비스, 프로그램의 사용을 제한"

**리스크**:
- 5회차에서 **Ollama, LM Studio** 설치 → 기업 PC에 비인가 소프트웨어 설치에 해당
- Chrome 확장 프로그램(Claude) 설치 → 확장 프로그램 관리 정책 위반 가능
- 기업 그룹 정책으로 설치가 차단된 경우 실습 자체가 불가

**개선 방안**:
- 수업계획서에 **플랜B 이미 포함** (설치 불가 시 웹 대안)
- 교육 전 IT팀에 **임시 설치 허용 요청** 또는 **교육용 별도 PC** 사용
- 사전 체크리스트에 "소프트웨어 설치 가능 여부" **이미 포함**

---

### 3. ⚠️ 2.7.1 암호화 정책 — AI에 전송되는 데이터 암호화

**기준**: "중요정보의 전송 시 암호화"

**리스크**:
- 실습 중 업무 데이터를 클라우드 AI에 입력 → 전송 구간 암호화(TLS) 확인 필요
- 대부분의 AI 서비스는 HTTPS를 사용하므로 전송 암호화는 충족
- 그러나 **저장 시 암호화** 정책은 AI 서비스마다 다름

**개선 방안**:
- 1회차에서 "AI 서비스는 HTTPS로 전송되지만, 저장/학습 정책은 다르다" 교육 → **이미 반영됨**
- 도구별 보안 조건표에 암호화 정보 추가 검토

---

### 4. ⚠️ 2.9.7 정보자산의 재사용 및 폐기 — 교육 후 데이터 정리

**기준**: "정보자산의 재사용 및 폐기 시 중요정보 완전 삭제"

**리스크**:
- 교육 중 AI에 입력한 데이터가 AI 서비스에 잔존할 수 있음
- Ollama 로컬 모델의 대화 히스토리가 PC에 남을 수 있음
- 교육 후 수강생 PC에 설치된 AI 도구와 잔여 데이터 정리 미언급

**개선 방안**:
- 6회차 수료 시 **"교육 데이터 정리 가이드"** 추가 필요:
  - AI 대화 기록 삭제 방법
  - Ollama 모델/캐시 삭제 방법
  - 교육용 더미 데이터 파일 삭제
- 수업계획서에 현재 **미포함** → 추가 권장

---

### 5. ⚠️ 2.2.1 주요 직무자 관리 — 교육 참가자 관리

**기준**: "개인정보취급자 목록 관리, 주요 직무자 최소 지정"

**리스크**:
- 교육을 통해 수강생이 **AI로 개인정보를 처리하는 방법**을 배움
- 교육 후 수강생이 **개인정보취급자 범위를 넘어** AI로 개인정보를 처리할 가능성
- 특히 Document AI로 영수증/계약서 파싱 시 개인정보 포함 가능

**개선 방안**:
- 1회차 데이터 분류에서 **"개인정보는 4등급 = AI에 절대 넣지 않는다"** 강조 → **이미 반영됨**
- 교육 후 기업 보안팀에 "AI 활용 가이드라인" 수립 권고

---

## C. 수업계획서를 ISMS-P 교육 증빙으로 활용하는 방법

ISMS-P 심사에서 **2.2.4 인식제고 및 교육훈련** 항목의 증빙자료로 활용 가능:

| 증빙 자료 | 수업계획서 대응 | 준비 필요 |
|-----------|---------------|----------|
| 교육 계획서 | 수업계획서 (Google/MS/Claude 트랙) | ✅ 있음 |
| 교육 자료 | 각 회차별 실습 자료, 템플릿 | 📝 제작 필요 |
| 출석부 | 수강생 명단 + 출석 기록 | 📝 양식 필요 |
| 교육 결과 보고서 | 6회차 프로젝트 발표 결과 | 📝 양식 필요 |
| 교육 평가 (설문/테스트) | 월요일 액션 플랜 + 만족도 설문 | 📝 양식 필요 |
| 미이수자 추가교육 계획 | 미포함 | 📝 추가 필요 |

### ISMS-P 심사 시 어필 포인트

> "본 교육은 AI 시대의 정보보호 인식 교육으로, ISMS-P 2.2.4(교육훈련)의 요구사항을 충족합니다. 
> 특히 데이터 분류 기준 수립(2.1.3), AI 생성 코드 보안 검증(2.9.1), 외부 서비스 보안 조건 이해(2.3.1)를 
> 실습 기반으로 교육하여, 형식적 보안교육이 아닌 실질적 보안 역량을 강화합니다."

## D. 종합 평가

| 구분 | 개수 | 상태 |
|------|------|------|
| ✅ 잘 지키는 기준 | **7개** | 교육 과정에 자연스럽게 반영됨 |
| ⚠️ 위반 리스크 | **5개** | 대부분 이미 대응책 포함, 일부 추가 필요 |

### 추가로 필요한 것 (2가지)

1. **교육 후 데이터 정리 가이드** (2.9.7 대응)
   - AI 대화 기록 삭제, Ollama 캐시 삭제, 교육용 파일 정리 방법

2. **ISMS-P 교육 증빙 양식 세트**
   - 출석부, 결과 보고서, 만족도 설문, 미이수자 추가교육 계획

이 2가지를 추가하면 **ISMS-P 인증 기업에서 정보보호 교육 증빙으로도 활용 가능한** 수업계획서가 됩니다.
